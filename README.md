# Beluga Planner — PWA-календарь v3.6

Статическое PWA-приложение без сервера, npm и сборщика. Подходит для GitHub Pages.

## Календарь

- месячный календарь;
- 4 фиксированных временных блока: 10:00–13:00, 13:00–16:00, 16:00–19:00, 19:00–22:00;
- типы: Работа / Учёба / Досуг;
- фактическое время начала и комментарий;
- до 4 точек под датой — по одной на каждый заполненный блок;
- Работа — красный, Учёба — синий, Досуг — зелёный.

## Напоминания

Внизу есть основная навигация `Календарь | Напоминания`.

В «Напоминаниях» две вкладки:

### Очередь

- задачи без назначенного календарного блока;
- новая задача по умолчанию неважная и несрочная;
- два независимых тоггла: «Важное» и «Срочное»;
- drag-and-drop за маркер слева для ручного изменения порядка (мышь и touch/pointer-интерфейс);
- кнопка «Запланировать»;
- редактирование, выполнение и удаление задач.

### Запланировано

- просмотр по дням;
- задачи сгруппированы по четырём календарным временным блокам;
- цвет блока наследуется от типа деятельности в календаре;
- отображается фактическое время начала;
- задачи можно выполнять, редактировать, переносить или возвращать в Очередь;
- в существующий календарный блок можно добавить задачу напрямую.

## Как работает планирование

Задачу можно назначить только в календарный блок, где на выбранную дату уже указан тип деятельности (Работа, Учёба или Досуг). Если таких блоков нет, окно планирования предлагает открыть выбранную дату в календаре.

Одна задача хранится одной записью. Незапланированная задача имеет `scheduled: null`; после планирования получает `date + slot`. Поэтому Очередь и Запланировано — два представления одних и тех же данных.

## Локальные данные и совместимость

IndexedDB сохранена под прежним именем `day-planner-db`.

В v3 версия базы повышена с 1 до 2 только для добавления нового object store `tasks`. Существующий store `days` не удаляется и не пересоздаётся, поэтому записи календаря из v1/v2 сохраняются после обновления.

Service Worker использует версионированный кэш; в v3.6 — `beluga-planner-v3-6`.

## Публикация через GitHub Pages

1. Распакуйте архив.
2. Замените содержимое текущего репозитория файлами этой версии.
3. Оставьте тот же GitHub Pages URL, чтобы origin и локальный IndexedDB не изменились.
4. После публикации откройте PWA. Новая версия кода подхватится, а старые календарные данные останутся.

## Локальный запуск

Из папки проекта:

```bash
python -m http.server 8000
```

Откройте `http://localhost:8000`.


## Исправление v3.1

Если предыдущая версия уже запускалась на том же локальном адресе, старый Service Worker мог продолжать отдавать старый `app.js`. В v3.1 CSS/JS/manifest имеют версионированные URL, а `app.js` подключается обычным `defer`-скриптом. Это предотвращает смешивание старого JavaScript с новым HTML и делает локальную проверку в Firefox надёжнее. IndexedDB не менялась.


## Исправления v3.2

- Поле «Фактическое начало» больше не растягивается на всю ширину блока в Safari/iOS.
- Нижняя навигация «Календарь | Напоминания» стала компактнее.
- Очередь получила собственный pointer-based drag-and-drop: карточка физически следует за мышью/пальцем, место вставки показывается плейсхолдером, порядок сохраняется в IndexedDB.
- Ручной порядок очереди больше не переопределяется статусом выполнения задачи.
- Тоггл важности: «Неважно» (зелёный) ↔ «Важно» (красный).
- Тоггл срочности: «Несрочно» (голубой) ↔ «Срочно» (жёлтый).
- Те же подписи используются в окне создания/редактирования задачи.
- Кэш Service Worker повышен до `day-planner-v3-2`; структура IndexedDB не менялась.


## Исправления v3.3

- Во вкладке «Запланировано» у каждой задачи всегда показываются оба состояния: «Важно/Неважно» и «Срочно/Несрочно», с теми же цветами, что и в Очереди.
- Добавлен drag-and-drop задач во вкладке «Запланировано». Задачи можно менять местами внутри блока и переносить между настроенными временными блоками выбранного дня.
- Меню действий унифицировано: в Очереди теперь доступны «Редактировать», «Запланировать», «Удалить»; у запланированной задачи — «Редактировать», «Перенести», «Вернуть в очередь», «Удалить». Внешний вид и компонент меню одинаковые.
- Кэш Service Worker повышен до `day-planner-v3-3`. IndexedDB и формат данных не менялись.


## Исправления v3.4

- Drag-preview во вкладке «Запланировано» переносится в `document.body`, поэтому `position: fixed` больше не зависит от `backdrop-filter` контейнера и не должен прыгать относительно курсора/пальца.
- Меню действий в Очереди и Запланировано имеет единую фиксированную адаптивную ширину (до 340 px) и одинаковое позиционирование.
- Меню автоматически открывается вверх, если снизу недостаточно места.
- Кэш Service Worker повышен до `day-planner-v3-4`; IndexedDB и формат данных не менялись.


## Изменения v3.5

- Выполненная задача автоматически перемещается в самый низ текущего списка как в «Очереди», так и внутри соответствующего временного блока во вкладке «Запланировано».
- Ручной порядок сохраняется отдельно среди невыполненных и среди выполненных задач.
- Drag-and-drop учитывает это правило: невыполненные задачи остаются выше выполненных, а выполненные можно переставлять внутри нижней группы.
- При переносе задачи между временными блоками её статус выполнения сохраняется и она попадает в соответствующую группу нового блока.
- Кэш Service Worker повышен до `day-planner-v3-5`; IndexedDB и формат данных не менялись.
